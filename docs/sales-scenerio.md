# Sales Scenario

## 1. Project Title
Smart Timetable (Team DigiTry)

## 2. Target User / Customer
- Primary user: RIC students who check their class schedule regularly
- Secondary user: Lecturers who need to communicate cancellations or room changes
- Decision-maker or admin role, if any: RIC academic office / admin staff who would maintain the official schedule data and review submitted reports

## 3. Situation / Context
It's 8:55 AM and a student is walking to Building 11, Room 304, for their 9:00 class based on the PDF timetable they checked last night. When they arrive, the room is dark and locked — the class was actually moved to Room 208 two days ago, but the only announcement was a message buried in a group chat the student doesn't check often.

## 4. Pain Point
The student wastes time walking to the wrong room, misses the start of class finding the real one, and has no fast way to flag that the PDF is wrong — so the next student who checks it hits the exact same problem. This is confirmed directly from Lab 03 customer discovery, not assumed.

## 5. Product Introduction
The product is introduced through a landing page (shared in the class group chat, a campus QR poster, and Instagram) that leads directly into the live prototype — not a slide deck or a promise of a future app. The first thing a visitor sees is the real schedule, with real course data, that they can click through immediately.

## 6. Value Message
For RIC students who experience unreliable, outdated class schedule information, our SmartTimetable web app helps them always know whether their next class is actually happening as listed by giving every class a live Confirmed / Room Changed / Cancelled status label and a one-tap way to report a mismatch so it gets fixed for everyone else too.

## 7. Sales Conversation / Pitch Moment
**Presenter:** "Quick question — has a class ever been in a different room than the PDF said?"
**Student:** "All the time. Usually I find out by showing up."
**Presenter:** "That's exactly why we built this." (opens the landing page) "Same schedule, but every class has a live status. Watch — I search your course code..." (demonstrates search) "...and it tells you right now if anything's changed. And if you're the one who notices something's wrong, you report it in like ten seconds, no name needed."
**Student:** "Wait, so if I report it, does it actually get fixed?"
**Presenter:** "Yeah — it goes straight to a dashboard the admin checks, and once they update it, everyone sees the new status immediately. We already tested this with real students — 95% could do it without any help from us."

## 8. Expected User Action
- Try the demo
- Give feedback
- Share with other students
