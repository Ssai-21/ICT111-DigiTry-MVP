## 2. Metrics Interpretation

The Power BI dashboard ("Lab 11 Startup/Product Metrics Dashboard — Team DigiTry") currently surfaces 4 of the 12 measures as headline cards — Total Records, New Submissions, Pending Cases, and Resolution Rate — plus a column chart breaking Total Records down by issue category, a bar chart by status, a line chart of activity events over time, a pivot table of activity by requirement, a detail table, and a combined slicer (User Role / Device Type / Status / Category). A 60% resolution rate with only 3 of 15 reports fully "Closed" (the rest "Claimed" or "Returned") suggests the team is actively working reports rather than letting them pile up, but there's still real room to close the loop faster — the current 2.27-day average resolution time is a reasonable baseline to try to beat in a later sprint. New Submissions (14) being nearly equal to Total Records (15 unique reports) confirms the activity log is capturing essentially every report correctly, which is a good sign the data model has no obvious gaps. The heavier weighting toward "SubmitReport" and "UpdateStatus" actions (11 admin updates) versus only 3 "ViewDashboard" events suggests admin/staff are doing the work but may not be checking the dashboard itself very often yet — worth watching once real usage data replaces this seeded sample. Mobile Activity Rate (44.4%) is a genuinely useful number for validating FR-14 (mobile-friendly design), since it's real evidence — not just a claim — that a large share of activity already happens on mobile even in this seeded dataset. The team should prioritize adding the remaining 8 measures (M-07 through M-12) as cards or a second dashboard page next, since right now the most operationally useful numbers (how long resolution actually takes, how much admin effort is going in per action, whether people revisit the dashboard) are defined and computable but not yet visible anywhere in the report.

## 3. Link to Final Prototype

The 4 cards already on the dashboard (M-01, M-03, M-04, M-06) map directly to what the SmartTimetable admin dashboard itself shows live (`#admin-dashboard` in `prototype/index.html`), so the Power BI dashboard functions as an independent, cross-checked confirmation of the same numbers rather than a duplicate built from scratch. The category and status breakdowns (column/bar charts) go further than the prototype's own dashboard currently does, and are a strong candidate to bring into the prototype itself as the "Issue Type Breakdown" card noted as remaining work in `docs/prototype-testing-notes.md`. The final submission should present both side by side: the live prototype dashboard as the actual product, and this Power BI file as the analytics layer proving the product's data holds up under real metric calculations — not just that it looks right.
